# 表单管理与编辑器体验优化需求

## 背景

当前表单系统的核心闭环已基本完成，但在实际体验中仍有几处影响效率和质感的问题：管理页首屏加载慢、删除确认使用浏览器原生对话框、草稿无法预览、新建表单自动保存后会出现二次加载、未命名表单无法自动保存。

本轮目标是修复这些体验问题，尽量保持后端模型和已有 API 结构稳定，仅做必要的数据读取和校验放宽。

## 目标

1. 优化 `/dashboard/forms` 首屏体验，表单列表不应在每次刷新时先空白等待 API 返回。
2. 删除表单时使用 shadcn `AlertDialog`，替代浏览器系统确认框。
3. 增加后台预览页 `/dashboard/forms/<uuid>/view`，让草稿表单也可以预览。
4. 新建表单自动同步后不应再次显示“正在加载表单编辑器”。
5. 新建表单只要有任何改动即可自动保存，允许未命名草稿存在。

## 已确认产品决策

1. 后台预览页使用预览模式，不允许真实提交；提交按钮禁用并显示预览模式。
2. 未命名表单在管理页显示为“未命名表单”可以接受。
3. 新建表单临时 slug 使用 `untitled-xxxxxx` 格式可以接受。

## 验收标准

1. 刷新 `/dashboard/forms` 时，表单列表随页面首屏出现，不再先显示 1-2 秒加载态。
2. 删除表单弹窗使用站内统一 shadcn 风格，显示表单名、不可撤销提示和删除中状态。
3. 草稿表单可以从编辑页和管理页打开 `/dashboard/forms/<uuid>/view` 预览。
4. 后台预览页不写入提交记录，提交按钮禁用，页面明确处于预览模式。
5. 新建表单后输入任意内容即可自动创建服务器草稿。
6. 新建自动保存完成后 URL 可更新为 `/dashboard/forms/<uuid>/edit`，但编辑器界面不闪回全屏 loading。
7. 已发布表单的公开填写页 `/forms/<slug>` 继续按发布版本读取，不受草稿预览影响。
8. `bun run lint` 和 `bun run build` 通过。

## 非目标

1. 本轮不新增评分、审核、审批流能力。
2. 本轮不重做数据库表结构。
3. 本轮不重做公开填写页视觉风格，只复用必要渲染能力支持后台预览。
4. 本轮不实现中文标题转拼音 slug。

## 风险与约束

1. `/dashboard/forms` 首屏优化应避免绕过管理员鉴权。
2. 后台预览页必须读取草稿快照，不能误用已发布版本。
3. 放宽自动保存校验时，发布校验仍必须严格，避免不完整表单被发布。
4. 新建后避免二次 loading 时，需要谨慎处理 URL 状态、activeFormId 和本地草稿 key 迁移。
