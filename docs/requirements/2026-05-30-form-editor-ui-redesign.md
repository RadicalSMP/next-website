# 表单编辑器前端重构需求

**日期：** 2026-05-30  
**关联分支：** `refactor/form`  
**运行模式：** `$vibe` / `interactive_governed`  
**范围状态：** 需求已冻结，等待执行

## 目标

在尽可能不改后端代码的前提下，重做后台表单创建与编辑体验，让表单编辑器接近 Google Docs、腾讯文档等成熟产品的工作台风格：空间更充足、编辑动线更直接、保存状态更可靠，并支持意外关闭后的恢复。

## 交付物

- 新的后台表单编辑器前端信息架构。
- 仍使用 `/dashboard/forms/new` 与 `/dashboard/forms/[id]/edit` URL 的无 sidebar 编辑体验。
- 后台表单列表入口改为新标签页打开编辑器。
- 自动保存机制：本地即时保存，数据合法时同步现有后端草稿接口。
- 发布前检查面板与明确的保存/发布状态反馈。
- 以现有表单 API 为主，不新增后端业务能力。

## 已确认约束

- 编辑页面仍使用 `/dashboard/forms/[id]/edit`，不新增 `/form-editor/[id]` 公开 URL。
- 编辑页面不显示 dashboard sidebar，以节约横向空间。
- 自动保存策略接受“双层保存”：本地立即保存，合法时同步服务器。
- 本轮只改后台表单编辑器与表单列表入口，暂不重做公开填写页和提交管理页。
- 后端代码尽可能不变动；优先复用现有接口：
  - `GET /api/forms/:id`
  - `POST /api/forms`
  - `PUT /api/forms/:id`
  - `POST /api/forms/:id/publish`
  - `GET /api/users?search=...`
- 当前分支已有上一轮表单修复的未提交改动，本轮实施时不得回滚用户或既有未提交改动。
- 本轮执行前不要自动提交；是否提交由用户决定。

## 非目标

- 不重构表单数据库结构。
- 不新增审核评分、审批流、多阶段审核能力。
- 不重做公开填写页。
- 不重做提交管理页。
- 不引入大型拖拽编辑框架，除非后续用户明确要求。
- 不把本地草稿同步到新后端草稿表。

## 产品验收标准

- 后台表单列表中的“创建表单”和“编辑表单”入口能在新标签页打开编辑器。
- `/dashboard/forms/new` 与 `/dashboard/forms/[id]/edit` 页面不显示 dashboard sidebar。
- 未登录或非管理员访问编辑器仍被拦截。
- 编辑器顶部有清晰的保存状态、预览入口、发布入口和返回入口。
- 表单标题、描述、字段标题、字段说明、字段选项可在中间画布直接编辑。
- 左侧题目大纲可新增、选择、复制、删除、排序字段。
- 右侧属性面板只承载当前字段的高级配置和表单级设置。
- 刷新或误关闭后，本地草稿能提示恢复。
- 数据满足后端校验时，自动同步到现有草稿接口。
- 发布前能展示校验结果，并阻止明显不完整表单发布。
- `bun run lint` 与 `bun run build` 通过。
- 桌面与移动端布局不溢出、不重叠。

## 技术验收标准

- 后端表结构不变。
- API 语义不变；如确需小幅后端调整，必须限制在兼容性或缓存失效边界，且在执行记录中说明原因。
- `FormBuilder` 被拆分为可维护的前端组件和状态 hook，避免继续扩大单文件复杂度。
- 自动保存不会在字段暂时不合法时反复打失败请求。
- 新建表单在满足最小合法条件后才创建服务端草稿，避免大量空草稿污染数据库。
- 发布动作前必须先尝试同步最新合法草稿。

## 风险与边界

- 同 URL 去 sidebar 需要调整 Next.js route group 归属：将编辑路由迁移到独立 route group，并删除原 dashboard layout 下的同路径页面，避免路由冲突。
- 新建表单自动同步可能产生草稿记录，需要用“最小合法条件 + debounce + URL replace”控制。
- `localStorage` 草稿需要按表单 ID 或新建会话隔离，避免不同表单互相覆盖。
- 现有未提交后端修复不能被本轮前端改造覆盖。

## 需求冻结结论

本轮只交付后台表单编辑器体验重构。核心原则是：前端信息架构大改，后端接口保持稳定；编辑器仍在 `/dashboard/forms/...` 路径下，但通过独立 layout 获得无 sidebar 的全屏工作台体验。
